Hephaestus MVP Efficiency Remediation Report
Date: 2026-06-03

Summary
Two strict Stage B gate defects and one task-store scheduling defect were corrected in this session. The result was a live shift from strict Stage B hard-fail to a clean passing window.

Root Cause 1
Problem
- Explicit task-store polling and redispatch overrides were being clamped up to production minimums, which broke low-latency test and harness behavior.
Fix
- src/task-store.ts now respects explicit override values for pollingIntervalMs, redispatchPendingAfterMs, and redispatchPendingMaxAfterMs.
Evidence
- node --test --import tsx test/task-store.test.ts passed.
- npm test passed after the change.

Root Cause 2
Problem
- Strict blocked gating counted the entire lifetime blocked backlog, including policy-quarantined tickets that should not define operational health.
Fix
- Added blockedWindowDays support to the autopilot policy, tickets CLI, and Stage B scripts.
- Blocked counts now use blockedAt/updatedAt/createdAt within the configured window and exclude quarantined categories.
Evidence
- Strict blocked gate moved from 82>40 to 5 actionable blocked tickets within 7 days.
- Autopilot stopped pausing on blocked-count-high.

Root Cause 3
Problem
- Review-wave backend reliability counted policy-boundary/quarantined attempts against the backend success ratio.
Fix
- Added computeBackendReliabilityMetrics in src/slo-metrics.ts.
- Review-wave now gates on actionable backend attempts only.
Evidence
- Ollama backend reliability moved from 55/167 (0.33) to 55/95 (0.58) for strict review-wave gating.
- Strict review-wave moved from NO-GO to GO.

- Strict operational gating now reflects actionable queue health.
- Autopilot no longer pauses because of quarantined backlog.

- Strict Stage B promotion readiness was restored in-session.

Interpretation
