Efficiency Qwen Test

Date: 2026-05-29
Project: Hephaestus

Abstract
This paper defines a Qwen-driven recovery program to restore Hephaestus as a net engineering efficiency multiplier. The plan matches the complexity level of prior roadmap papers by combining admission hardening, policy-friction burn-down, wave-gated operations, and telemetry-driven remediation. The implementation target is 20 tickets executed through Hephaestus with Qwen as the active local model. Success is measured by effective code mutation per ticket, not just queue-state transitions.

Problem Statement
Recent assisted runs exposed a persistent gap between orchestration activity and delivered code mutation:
- tickets can reach completed state with low or zero meaningful repository mutation
- denial and envelope friction consumes execution budget
- queue-state files change while product/runtime surfaces stay flat

The core objective is to convert control-plane activity into measurable delivered changes while preserving governance safety.

Thesis
Efficiency can recover if Hephaestus is operated as a constrained mutation pipeline:
1. high-quality bounded admission
2. wave-gated release of work
3. low-friction verification policy
4. mandatory mutation evidence per ticket
5. explicit post-wave efficiency accounting

Roadmap: Qwen Efficiency Recovery Program

Phase 0: Baseline and Guardrails
Goal: establish hard reference points and prevent noisy execution.
- Freeze unrestricted bulk seeding.
- Require explicit expected signal in every ticket.
- Define mutation evidence policy:
  - each completed ticket must identify touched paths and verification command outcome
- Gate thresholds:
  - completion rate >= 0.70
  - superseded rate <= 0.20
  - blocked growth <= +5 per wave
  - allowlist denial rate <= 0.08
Outcome: deterministic operating envelope before new wave admission.

Phase 1: Admission Contract Tightening
Goal: prevent low-quality tickets from entering execution.
- Enforce action-verb ticket syntax and single-scope targeting.
- Require exactly one accepted verification command per ticket.
- Add expected-signal sentence in canonical form.
- Reject mixed multi-surface tickets and auto-split broad intents.
Outcome: higher completion probability and lower retry fan-out.

Phase 2: Policy Friction Reduction
Goal: reduce avoidable blocked/denied attempts.
- Normalize accepted verification command variants.
- Track stable reason-code buckets for denial families.
- Prioritize remediation tickets for top denial causes.
Outcome: less time spent in non-mutating blocked paths.

Phase 3: Wave-Gated Throughput Control
Goal: produce compounding output without queue churn.
- Run four waves of 5 tickets (20 total).
- Admit next wave only after gate checks.
- If any gate fails, run remediation-only tickets.
Outcome: bounded queue pressure with measurable delivery per wave.

Phase 4: Mutation-Centric Telemetry
Goal: optimize for delivered repository change, not activity volume.
- Track per-wave:
  - completed tickets
  - files mutated
  - insertions/deletions in targeted scope
  - effective mutation per completed ticket
- Compare against manual and prior assisted baselines.
Outcome: direct efficiency accountability.

Execution Method
1. Set active model to qwen3-coder:30b.
2. Seed exactly 20 tickets from the backlog above.
3. Execute Hephaestus in single-pass run mode until no pending tickets remain.
4. Capture ticket outcomes and repository mutation evidence.
5. Compare effective code changes with:
   - last manual baseline
   - previous assisted baseline

Measurement Framework
Primary metric: effective mutation volume in targeted scope.
- Targeted scope: docs/metrics/qwen-wave/**
- Effective change: files created/updated plus insertion/deletion counts in targeted scope.

Secondary metrics:
- completion rate in 20-ticket wave
- mutation-per-completed-ticket ratio
- governance churn indicators (blocked/superseded)

Baseline References
- Manual baseline (commit dcf82a8): 3 files, +128/-28 (156 total line deltas).
- Previous assisted baseline: targeted code/doc scope yielded 0 effective deltas; queue-state deltas observed in AGENT.md and TASKS.md.

Success Criteria For This Qwen Test
- At least 14 of 20 tickets complete.
- Non-zero targeted mutation in qwen-wave scope.
- Mutation-per-completed-ticket improves over previous assisted baseline.
- Evidence supports equal or better operational efficiency than prior assisted run.

Conclusion
This roadmap restores efficiency by coupling strict admission quality with mutation evidence and wave-gated control. The decisive signal is not how many tickets are processed, but how much validated repository change is produced per completed ticket under governance constraints.
