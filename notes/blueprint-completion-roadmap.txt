Purpose

Decision Boundary
- Complete supervised autonomy: yes.
- Complete unconstrained autonomy: no.

Delta-Only Execution Rules (Anti-Overlap)
1. Every roadmap item must be classified before work starts:
  - consolidate (normalize existing behavior)
  - harden (tests, invariants, observability)
  - extend (incremental capability on existing path)
  - net-new (no current implementation path)
2. No item may proceed without an Existing Coverage Check listing:
  - current modules touched
  - current tests already covering behavior
  - current artifacts/APIs likely affected
3. No-Duplicate Gate (required for merge):
  - no parallel policy engine for an already-governed decision path
  - no duplicate schema for an existing artifact domain
  - no duplicate command when current command can be extended
  - no duplicate report if current report can be versioned or augmented
4. Delta Statement (required in ticket/PR):
  - current behavior
  - target behavior
  - minimal change path
  - rollback path
5. Reuse-First Rule:
  prefer config/profile/schema extension before introducing new runtime components.

Duplicate-Risk Scoring
- Low: clearly net-new capability with no existing module overlap.
- Medium: extends existing module with bounded migration impact.
- High: touches existing critical path where alternative implementation already exists.
High-risk items require architecture sign-off before implementation.

Working Definition of Completion
Blueprint completion is achieved when:
1. Always-on operation is bounded by policy and health guardrails.
2. Risky actions are approval-gated and auditable.
3. Recovery and rollback are reliable and test-backed.
4. Capability claims are tied to deterministic evidence artifacts.
5. Cross-platform operator flows are documented and validated in CI.

Status Rubric (Objective)
- Not started: <25% of deliverables implemented and no reliable test coverage.
- Partial: 25-74% of deliverables implemented or coverage/integration incomplete.
- Mostly complete: >=75% of deliverables implemented with passing tests, but one or more hard gates pending.
- Complete: 100% deliverables implemented, hard gates enabled, and CI/ops verification passing.

Formal Invariants (Must Hold)
1. No high-risk mutation executes without recorded gate decision.
2. Every mutating attempt has attributable workspace and policy provenance.
3. Promotion cannot become active after failed health validation.
4. Required evidence artifacts must exist and validate before release-candidate promotion.

Formal Evaluation Protocol (Research + Operations)
- Hypotheses:
  - H1: supervised autonomy improves queue throughput without increasing rollback rate.
  - H2: risk-tier gating reduces unsafe mutation attempts at acceptable operator latency.
  - H3: checkpoint + rollback policy reduces mean recovery time under injected failures.
- Evaluation corpus:
  - fixed benchmark ticket set (low/medium/high risk classes), versioned by date and schema.
- Method:
  - compare baseline vs treatment windows with identical ticket mix constraints.
  - report confidence intervals for key deltas (throughput, rollback rate, approval latency).
- Validity controls:
  - document internal validity threats (ticket mix drift, operator behavior variance).
  - document external validity limits (repo size, domain specificity, model/provider effects).

Research-Grounded Design Constraints (From Active Sources)
1. Situation awareness requirement (Endsley1995):
  operator surfaces must provide perception, comprehension, and projection, not raw status only.
2. Trust calibration requirement (LeeSee2004):
  gates should optimize appropriate reliance; track both overtrust and undertrust outcomes.
3. Unsafe control action analysis (LevesonThomas2018STPAHandbook):
  each autonomy control path must map to explicit hazards, controls, and feedback channels.
4. Snapshot consistency requirement (ChandyLamport1985):
  checkpoint/replay must use explicit capture boundaries so historical reconstruction is consistent.
5. Compensation-first reliability requirement (Helland2007LifeBeyondDistributedTransactions):
  long-running workflows must prefer compensating actions over implicit global-transaction assumptions.
6. Invariant testing requirement (ClaessenHughes2000):
  lifecycle and policy modules require property-based tests, not scenario tests alone.
7. Realistic benchmark requirement (Jimenez2024SWEBench):
  evaluation must include repository-realistic issue-to-fix tasks with environment constraints.
8. Simplicity baseline requirement (Xia2024Agentless):
  complex autonomous workflows must be compared against simpler staged baselines before adoption.

Effects of New Research Intake (2026-06-02)
Accepted effects on blueprint direction:
1. Safety update constraint effect:
  policy updates must be constrained and safety-checked before activation, not only runtime-monitored after activation.
2. Causal incident quality effect:
  incident records must include explicit causal attribution fields and confidence notes, not correlation-only summaries.
3. Trust dynamics effect:
  approval policy tuning must account for intervention timing and operator trust dynamics, not approval rate alone.
4. Canary interpretation effect:
  promotion decisions must include canary exposure interpretation rules, not binary canary pass/fail only.
5. Multi-objective tuning effect:
  safety-throughput-latency tradeoffs should be tuned using explicit multi-objective criteria.
6. Socio-technical response effect:
  incident runbooks must include human coordination steps and communication paths, not tool actions only.

Intake quality caveat (applied governance rule):
- automated acquisition can return low-fit papers; every new source must pass a domain-fit curation gate before becoming a long-term active source.

Track A: Close Partial Foundations (P2-P5)
A1. Scheduler policy completion
Work type: extend + harden
Duplicate-risk score: medium
- Add explicit cooldown and backoff strategy contract.
- Add concurrency policy contract and duplicate-attempt race tests.
Exit criteria:
- Scheduler behavior deterministic under restart and contention.
- Restart fault-injection suite passes with duplicate-attempt incidence rate = 0 in test window.
- Cooldown and backoff parameters are externally configurable and reflected in runtime diagnostics.
- Queue fairness SLO and starvation upper bound are defined, measured, and met.

A2. Risk-tier policy engine
Work type: extend
Duplicate-risk score: high
- Add risk scoring module with weighted factors.
- Map risk tiers to allow/approve/deny paths.
- Add score decomposition output and causal-reason fields for each gate decision.
Exit criteria:
- All high-risk actions require approval.
- Gate outcomes recorded with reason codes.
- Weekly gate calibration review computes false-positive and false-negative rates.
- Policy threshold changes require changelog entry and before/after metric snapshot.
- Trust calibration report includes overtrust and undertrust indicators for operator reliance.
- Gate decisions include an auditable score breakdown and decision rationale payload.

A3. Checkpoint and recovery contract
Work type: extend + harden
Duplicate-risk score: medium
- Add checkpoint policy module:
  - time-based snapshots (fixed interval)
  - event-based snapshots (pre-patch, pre-verify, pre-promotion)
- Add rollback verification tests.
Exit criteria:
- Recovery succeeds to known checkpoint under defined failure scenarios.
- Recovery runbook validated by automated fault harness at least once per release cycle.
- Recovery RTO p95 target is defined and met in validation runs.
- Snapshot replay consistency checks pass for sampled checkpoint windows.
- Compensation tests pass for side effects that cannot be safely rolled back.

A4. Evidence contract enforcement in CI
Work type: consolidate + harden
Duplicate-risk score: medium

- Add CI job to validate artifact presence, schema, and timestamp freshness.
Exit criteria:
- CI fails when required evidence artifacts are missing or invalid.
- Release-candidate pipeline blocks promotion when artifact contract checks fail.
- Artifact schema version mismatch is treated as hard failure unless compatibility mode is explicitly enabled.
- CI publishes baseline-vs-treatment benchmark summaries and blocks on missing benchmark evidence.

Re-Compiled KPI Set

Core Outcome KPIs
- Attempt success rate (policy-compliant completed attempts / started attempts)
- Approval latency by risk tier
- Rollback success rate
- Queue-to-completion latency by priority
- Trust calibration gap (overtrust and undertrust indicator rate)
- Causal attribution completeness rate in incident records
- Canary interpretation error rate (rollbacks attributable to misread canary exposure)

Reliability KPIs
- Scheduler uptime
- Duplicate-attempt incidence rate
- Mean time to detect failed attempt
- Mean time to recover blocked attempt
- Scheduler fairness index and starvation bound compliance
- Snapshot replay consistency pass rate
- Compensation success rate for non-rollbackable side effects

Evidence KPIs
- Required artifact completeness ratio
- Artifact schema validation pass rate
- Source-drift and missing-evidence gate breach frequency
- Benchmark evidence completeness (including simple staged baseline comparisons)
- New-source curation pass rate (domain-fit approved / intake candidates)

Risk Register (Top Items)
1. Risk-tier overblocking increases operator burden.
Mitigation: monitor gate precision, tune thresholds by profile.
Calibration cadence: weekly threshold review; monthly policy stability review.

2. Cross-OS parity introduces script drift.
Mitigation: enforce CI matrix and maintain script compatibility tests.

3. Checkpoint overhead impacts throughput.
Mitigation: apply event-based checkpoints to high-risk transitions; tune time interval.

4. Evidence contract brittleness blocks useful progress.
Mitigation: version schemas and support strict plus transitional validation modes.

5. Autonomy complexity creep outperforms governance value.
Mitigation: require staged-baseline comparison before increasing agentic complexity.

6. Automated research intake semantic drift introduces low-fit references.
Mitigation: enforce domain-fit curation gate and placeholder-replacement workflow before source promotion.
