# LeeSee2004

Citation: Lee, J. D., and See, K. A. (2004). Trust in Automation: Designing for Appropriate Reliance. Human Factors, 46(1), 50-80.

Public URL or DOI: https://doi.org/10.1518/hfes.46.1.50.30392
Local Copy: not present
Status: note
Blueprint Phases: D3-D6

## Summary

- Trust should be calibrated, not maximized.
- Systems should help operators rely on automation when it is warranted and disengage when it is not.
- Overtrust and undertrust both degrade system performance and safety.
- Interface signals and policy boundaries shape trust more than slogans do.

## Relevance To Hephaestus

- Approval thresholds and autopilot boundaries should be designed for appropriate reliance.
- The system needs evidence-rich explanations when it asks for approval or resumes held work.
- D3-D6 should treat operator trust as an architectural concern, not a documentation concern.

## Hephaestus Would Be Worse Without It

Hephaestus could drift toward either intrusive manual gating or unsafe over-automation without a principled middle ground.
